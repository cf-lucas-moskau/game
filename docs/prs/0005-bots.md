## Summary

## Checks

Bots are ordinary clients: they read the world and emit the same commands a player sends,
so the simulation cannot tell them apart from humans (and replays work from command logs).

- `perception.js`: read-only snapshot (fronts, towers, power estimate, tower-dive checks, lead prediction).
- `bot.js`: utility-scored states (lane, trade with kiting, all-in on focus target, retreat,
  siege with tank checks, push after winning fights), shopping in `BUILDS` order,
  summoner spells, difficulty = think interval (400/250/150 ms), aim error, ability rate.
- `heroes.js`: per-hero scripts using each signature mechanic (Morrow rewinds when history
  health is higher, Vesper draws loops and escape-cutting walls, Gus dismounts to poke and
  remounts when low, Brindle banks bees for the Dome, Auctioneer repossesses expensive items).
- `tools/simulate.mjs`: headless bot-vs-bot matches for balance.

**Bugs found by bot matches and fixed here**
- Recycled entity records lost their id (reset to 0), so dying minions despawned tower 0.
  Structures are now never recycled; regression tests added.

**Pacing** (10 simulated matches): average 9.7 min, max 11.4 min, blue 4/10.
Changes: tower 2300 HP, Heartstone 3000 HP, minion siege multipliers, minion growth 5%/min,
sudden death at 10:00 with Heartstone decay 1.2%/s so every match ends.
Brindle's bee economy raised (heroes give 2, in-combat trickle, slower decay) after bots showed 15 bees was unreachable.

Tests: full bot match ends, towers fall, bots buy items, command-log replay produces an
identical state hash, every hero casts all four abilities.
