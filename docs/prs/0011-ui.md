# PR #11: UI and the playable loop

Branch: `claude/goal-test-aotoyo` (GitHub)

## Summary

The game can now be played start to finish without URL parameters:
hero select -> match -> end screen -> Play again / Rematch -> hero select.

- `app/app.js`: application flow. Hero select runs over a live bot match (the spectate view) as
  backdrop; each match gets a fresh canvas, session, input devices and UI, and is torn down
  completely afterwards (`Renderer.dispose` releases the GL context). URL shortcuts (`hero=`,
  `heroes=`, `play=`) still jump straight into a match for development, tests and benchmarks.
- Hero select (`ui/menu.js`): the whale picks a random hero, one reroll, full kit description,
  bot difficulty (remembered), controls help for desktop or touch, settings.
- HUD (`ui/hud.js`, `ui/minimap.js`): the lane strip across the top (structures with health and
  vulnerability, minions, heroes, camera window, whale-roll warning on the endangered edge), team
  kills, match clock (turns red in sudden death), kill feed, banners (objective, whale roll, towers,
  sudden death, your kills), respawn countdown with a vignette, portrait with level/XP ring,
  HP with damage trail and shield, resource bar per hero resource, abilities with cooldown sweeps,
  rank pips, "not enough resource" state and a ready flash, D/F, six item slots with active
  cooldowns, gold (pulses when you can shop), tooltips.
- Shop (`ui/shop.js`, P or the gold button): browse anywhere, buy and sell at the fountain or while
  dead, reasons for disabled items, recommended build per hero. Purchases are `BUY`/`SELL` commands
  through the transport.
- Scoreboard (Tab), Esc menu (resume, settings, surrender with confirmation, leave), settings
  (quality, camera shake, damage numbers, simulated ping; persisted), F3 perf overlay with
  "Copy report", pooled floating combat numbers, end screen with both teams' stats.
- Sim: `CMD.SURRENDER` (validated, deterministic, accepted while dead, `state.surrendered`), tested.
- Touch: the right thumb keeps `input/touch.js`; the HUD moves to a compact top-left dock.
- Fonts bundled offline (Gloock for titles, Bricolage Grotesque for HUD numbers).

## What was measured

- New gated metric `uiUpdateP95Ms` (budget 1.5 ms): the whole UI update per frame.
- Two layout bugs found by measurement and fixed before merge (details in docs/PERF.md):
  a forced reflow inside the renderer's event drain (floating numbers; emulated-phone render update
  p95 0.8 -> 2.8 ms) and per-frame layout reads (UI p95 desktop 0.9 -> 0.3 ms, phone 3.3 -> 1.0 ms).
- e2e (gate step) now drives the loop through the real UI: hero select, reroll, Fight, shop purchase,
  Escape, scoreboard, surrender, end screen, Play again, second clean match. A natural ending
  (sudden-death Heartstone decay) was verified separately with `?skip=630`.

## bench-eval: gcPauseMaxMs on the emulated phone

The only failing check is `mobile-low.gcPauseMaxMs` = 16.54 ms (budget 5): one MajorGC finalization
at a 3.9x CPU throttle (about 4.2 ms unthrottled). Total GC time over the run is unchanged against the
VFX build (249 vs 253 ms), and in this container the pre-VFX `main` already measured 13.17 ms (see
docs/prs/0010-vfx.md and docs/PERF.md). Budgets unchanged; merged with this justification.
